🧰 Custom Tool

Built from 📁 Files & commands ⚡ Custom commands 🧠 Persistent memory

What you'll build

Whatever you want. The other four demos are concrete recipes; this page is the skeleton underneath them. Bring your own idea — a Friday wrap-up email, a competitive-intel scraper, a meeting-notes summarizer, an auto-generated retro template — and shape this scaffold around it. The pattern is always the same: name the command, list its inputs, describe what it should produce.

Your tool's output appears here.

What you'll need

  • Claude Code installed and signed in
  • An idea, even a fuzzy one
  • A folder for the project (e.g., ~/projects/my-tool) — optional, but tidy

Step 1 — Sketch your idea

Before you paste anything, answer three quick questions. You don't need polished answers; rough sentences are fine. Claude will sharpen them with you.

  • What's the goal? One sentence. "Generate a Friday email summarizing what my team shipped this week."
  • What goes in? Files in a folder? URLs? Your calendar? Nothing — just your prompt? Pick one or two.
  • What comes out? A magazine-style HTML page? A markdown report? Plain text in chat? An email draft? Be specific.

If you can answer those three, you have enough to start.

Step 2 — Ask Claude to build your slash command

Open Claude Code in any folder. Paste this skeleton, swap your specifics into the [FILL IN: ...] placeholders, and hit enter. Claude will write the slash command file at ~/.claude/commands/[FILL IN: command-name].md for you. If you're unsure how to fill a placeholder, leave it as a question — Claude will ask follow-ups.

Create a Claude Code slash command at ~/.claude/commands/[FILL IN: command-name, e.g. "friday-wrap"].md.

GOAL
- [FILL IN: one sentence describing what this tool does]

INPUTS
- [FILL IN: what should Claude read? Examples: markdown files in notes/, a list of URLs in sources.md, Microsoft 365 calendar/email, or "nothing — just run on the prompt"]

PROCESSING
- [FILL IN: what should Claude do with the inputs? Examples: summarize, rank by relevance, filter to the last 7 days, reformat, draft a reply]

OUTPUT
- [FILL IN: what should the tool produce? Examples: site/index.html (magazine layout), output/YYYY-MM-DD.md, an email draft pasted into chat, a one-page PDF]

CUSTOMIZATION KNOBS
- [FILL IN: what should be easy to tweak later without rewriting the command? Examples: lookback window, tone, sections to include, scoring threshold]

GUARDRAILS (optional but recommended)
- [FILL IN: anything Claude should NOT do. Examples: "external sources only — don't touch M365", "don't fabricate items", "don't overwrite files outside site/"]

Write proper YAML frontmatter (description: ...) and a clear prompt body so the command works on the first run. If any of my answers are vague or contradictory, ask me follow-ups before writing the file.
What the generated file should look like

The shape Claude writes will resemble this — a YAML header with a description, a short purpose statement, and numbered steps. The specifics depend on what you put in the prompt above.

---
description: [one-line summary of what this tool does]
---

You are building [the thing the user described in GOAL].

SCOPE
- [Any guardrails the user listed, restated plainly]

INPUTS
- [Each input file or data source, with the format Claude should expect]

WHAT TO DO
1. Read each input.
2. [Processing step 1]
3. [Processing step 2]
4. Write the output to [path].
5. End with a short summary in chat.

CUSTOMIZATION
- [Each knob the user named, with its default value]

NOTES
- Be honest in chat output if something fails.
- Don't fabricate data.
- Re-running should overwrite the output, not append.

Use the existing demos as longer reference recipes — e.g. recipes/daily-brief.md.

Step 3 — Run it

From your project folder, in Claude Code:

> /[your-command-name]

First run will likely surface gaps — a missing input file, an ambiguous instruction, a source that doesn't return what you expected. Tell Claude what's off and let it adjust the command body. Two or three iterations is normal.

Step 4 — Iterate

Your command lives at ~/.claude/commands/your-command.md. Open it. It's just markdown — read it, edit it, ask Claude to refactor it. Common iterations:

  • Tighten the prompt. Add an example of a good output, or a counter-example of one to avoid.
  • Add a customization knob. Pull a hardcoded value out into a variable the user can change.
  • Add a guardrail. When Claude drifts into territory you didn't want, name that territory explicitly in the prompt.
  • Add persistent memory. A preferences.md or history.md file in the project folder that Claude reads (and optionally updates) every run.

Where to go from here

Browse the toolbox for what's available — web fetch, Microsoft 365, sub-agents, hooks, more connectors. Most tools your team uses have an MCP connector; if your idea needs one that isn't wired up yet, that's a conversation worth having. The other four demos are also fair game to clone — copy a recipe from recipes/ as your starting point and reshape it.
