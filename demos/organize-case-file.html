🗂️ Organize Case File

Built from 📁 Files & commands 🤝 Sub-agents ⚡ Custom commands

What you'll do

Point Claude at a messy folder — loose PDFs and Word docs, statements, correspondence, ACDVs, zip files with more zips inside — and get back a clean, numbered organized/ tree of renamed copies, with a per-folder README, a master index, and a reconstructed timeline. Your originals are never touched. The index it builds is what the next workflow drafts from.

A 200-file dump → an organized/ tree by litigation lifecycle, fully indexed.

This one's already a skill

Organizing case files is a repeatable job, so it's packaged as the organize-for-me skill — a saved set of instructions Claude already knows. If it's installed, you can just say /organize-for-me (or ask Claude to "organize this folder") and it runs. The prompt below is the plain-language version of what that skill does, so the behavior is the same either way.

What you'll need

  • Claude Cowork open on an approved, no-training tier (see Working safely with client data)
  • The case folder you want organized — in whatever state it's in
  • A backup of that folder first (the run copies, never moves — but back up anyway)

Step 1 — Open the folder in Cowork

Point Cowork at the case folder. Everything it writes goes into a new organized/ subfolder; nothing outside it is renamed, moved, or deleted.

Step 2 — Paste this into Cowork

If the organize-for-me skill is installed, you can skip the paste and just run /organize-for-me. Either way, this is the instruction:

Organize this folder of case files so I can actually use it. It's a mess of PDFs, Word docs, statements, correspondence, and zip files — some with zips inside them.

Please:
- Look at everything first, and extract every zip (including zips inside zips).
- Read the documents by fanning out sub-agents in parallel — one per document, grouping small similar files — so it goes fast. For each file, note its type, its date, a short summary, the dated events in it, and anything odd (missing pages, exposed personal info).
- Copy — never move — every file into a clean, numbered folder structure under organized/, renamed like "2025-02-14 ACDV Response.pdf". Put anything you can't read or place into organized/99-Unclassified/ — never drop a file silently.
- Build the index: a _README.md in each folder, a master organized/README.md with a case summary and a table mapping every new file back to where it came from, and organized/TIMELINE.md with every dated event in order, each citing its source.
- When you're done, check that the number of files in organized/ matches what you started with, and confirm you didn't touch anything outside organized/.

Leave my original files exactly as they are — the original layout is evidence. The only thing you create is the organized/ folder. If a file is password-protected or unreadable, flag it rather than skipping it. If an organized/ folder already exists, don't overwrite or merge into it — tell me and ask first. And if anything is unclear — you can't tell which files belong to this case, or there's a file type you don't recognize — stop and ask me before going ahead rather than guessing.

What Cowork does

The heavy lifting is Phase 2: instead of reading hundreds of files one-by-one (which is slow and fills up Claude's memory), it dispatches a fleet of sub-agents that read in parallel — each returns a small structured note about its file. Those notes become the index.

Phase 1 · Inventory
  Found 213 files (47 of them inside 6 zips — extracted)
Phase 2 · Understand — fanning out sub-agents
  Dispatched 28 readers in parallel (small files batched):
  ├─ payment statements (12) ........ done
  ├─ ACDV responses (9) ............. done
  ├─ correspondence (31) ............ done
  ├─ forbearance letters (7) ........ done
  └─ … 24 more batches .............. done
Phase 3 · Arrange — copying into organized/ (originals untouched)
Phase 4 · Document & verify
  Wrote 6 folder READMEs + organized/README.md + organized/TIMELINE.md
  ✓ 213 files in organized/ == 213 inventoried
  ✓ nothing outside organized/ changed
  ⚠ 2 files → 99-Unclassified (1 password-protected, 1 corrupt)

What you get

A predictable tree by litigation lifecycle — the same shape every case, so you always know where to look:

organized/
├─ README.md            ← case snapshot + manifest (the index)
├─ TIMELINE.md          ← every dated event, each sourced
├─ 01-Loan-Origination/
├─ 02-Servicing-and-Payments/
├─ 03-Disputes-and-Credit-Reporting/
├─ 04-Correspondence/
│  ├─ Incoming/
│  └─ Outgoing/
├─ 05-Government-and-Program/
└─ 99-Unclassified/     ← unreadable / unplaceable, never dropped
What organized/README.md looks like

The master index: a snapshot, a folder map, a manifest that traces every copy back to its original, and the flags your sub-agents raised.

# Case File — J. Borrower / Acct ****1234

## Case snapshot
Loan-servicing dispute: borrower alleges mis-reported late payments after a
2024 forbearance. File spans origination (2019) through a 2025 ACDV exchange.

## Folder map
- 01-Loan-Origination — disclosures, promissory note
- 02-Servicing-and-Payments — statements, payment history, forbearance
- 03-Disputes-and-Credit-Reporting — ACDVs, dispute letters
- 04-Correspondence — borrower letters, incoming & outgoing
- 05-Government-and-Program — NSLDS, IDR records
- 99-Unclassified — 2 files (1 password-protected, 1 corrupt)

## Manifest (excerpt)
| Organized file | Original source |
| --- | --- |
| 02-Servicing-and-Payments/2024-08-01 Forbearance Approval.pdf | dump/scan0098.pdf |
| 03-Disputes-and-Credit-Reporting/2025-02-14 ACDV Response.pdf | zips/acdv_batch.zip → ACDV_0214.pdf |

## Flags
- PII: full SSN visible on 2019 application (p. 2) — redact before sharing.
- Gap: payment history skips Sep–Nov 2024 — pages may be missing.
