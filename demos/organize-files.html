🗂️ Organize Files

Built from 📁 Files & commands 🤝 Sub-agents ⚡ Custom commands

What you'll do

Point Claude at a messy folder — loose PDFs and Word docs, spreadsheets, statements, correspondence, zip files with more zips inside — and get back a clean, numbered organized/ tree of renamed copies, with a per-folder README, a master index, and a reconstructed timeline. Your originals are never touched. The index it builds is what the next workflow drafts from.

A 200-file dump → an organized/ tree, grouped and fully indexed.

This one's already a skill

Organizing files is a repeatable job, so the legal version is packaged as the organize-for-me skill — a saved set of instructions Claude already knows that applies a fixed legal taxonomy (Loan Origination, Servicing, Disputes, Correspondence, etc.). If it's installed, you can just say /organize-for-me and it runs. The generic version below first asks how you want things grouped — by date, type, topic, or your own scheme — then organizes accordingly. Pick the tab that fits your situation.

What you'll need

  • Claude Code or Claude Cowork
  • The folder you want organized — in whatever state it's in
  • A backup of that folder first (the run copies, never moves — but back up anyway)

Step 1 — Open the folder

Point Claude at the folder. Everything it writes goes into a new organized/ subfolder; nothing outside it is renamed, moved, or deleted.

Step 2 — Choose your example and paste the prompt

I have a folder of mixed files I need to make sense of. Before you start, ask me 2-4 questions — what these files are, how I'd like them grouped (by date? type? topic?), how I want them named, and whether anything is sensitive. Wait for my answers.

Then:
- Look at everything first, and extract any zip files (including zips inside zips).
- Read the files by fanning out sub-agents in parallel — one per file, grouping small similar files — so it goes fast. For each, note its type, date, a short summary, and anything odd.
- Copy — never move — every file into the structure I asked for, under a new organized/ folder, renamed clearly. Put anything you can't read or place into organized/99-Unclassified/ — never drop a file silently.
- Build an index: a short README in each folder, a master organized/README.md mapping every copy back to its original, and organized/TIMELINE.md of any dated events.
- Check the counts match and confirm you didn't touch anything outside organized/.

Leave my originals exactly as they are. If an organized/ folder already exists, or anything's unclear, ask me before going ahead.

If the organize-for-me skill is installed, you can skip the paste and just run /organize-for-me. Either way, this is the instruction:

Organize this folder of case files so I can actually use it. It's a mess of PDFs, Word docs, statements, correspondence, and zip files — some with zips inside them.

Please:
- Look at everything first, and extract every zip (including zips inside zips).
- Read the documents by fanning out sub-agents in parallel — one per document, grouping small similar files — so it goes fast. For each file, note its type, its date, a short summary, the dated events in it, and anything odd (missing pages, exposed personal info).
- Copy — never move — every file into a clean, numbered folder structure under organized/, renamed like "2025-02-14 ACDV Response.pdf". Put anything you can't read or place into organized/99-Unclassified/ — never drop a file silently.
- Build the index: a _README.md in each folder, a master organized/README.md with a case summary and a table mapping every new file back to where it came from, and organized/TIMELINE.md with every dated event in order, each citing its source.
- When you're done, check that the number of files in organized/ matches what you started with, and confirm you didn't touch anything outside organized/.

Leave my original files exactly as they are — the original layout is evidence. The only thing you create is the organized/ folder. If a file is password-protected or unreadable, flag it rather than skipping it. If an organized/ folder already exists, don't overwrite or merge into it — tell me and ask first. And if anything is unclear — you can't tell which files belong to this case, or there's a file type you don't recognize — stop and ask me before going ahead rather than guessing.

The heavy lifting is Phase 2: instead of reading hundreds of files one-by-one (which is slow and fills up Claude's memory), it dispatches a fleet of sub-agents that read in parallel — each returns a small structured note about its file. Those notes become the index.

Why it matters

Two payoffs. First, you can find anything in seconds, and the timeline is reconstructed for you. Second — and this is the part that compounds — the manifest and timeline are a real index. The next workflow drafts from that index instead of re-reading every PDF, so the work you do here pays off again every time you draft.
