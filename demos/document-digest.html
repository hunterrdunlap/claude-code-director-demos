📄 Document Digest

Built from 📁 Files & commands 🤝 Sub-agents

What you'll do

Drop one long document — a contract, deposition transcript, brief, or regulatory filing — into a folder, paste one prompt into Claude Cowork, and get back a structured digest plus a timeline. Every claim cites the page it came from, so you can check it. This is the headline of the set: it turns an hour of reading into a faster first pass — a digest you still verify against the pages it cites.

outputs/DIGEST.md — parties, key terms, deadlines, risks, open questions; every line page-cited.

What you'll need

  • Claude Cowork open on an approved, no-training tier (see Working safely with client data)
  • A working folder with an inbox/ subfolder, and one digital document inside it (text selectable, not a scan)
  • An empty outputs/ subfolder for the results (Cowork will create it if missing)

Step 1 — Drop in one document

Put a single document in inbox/. Keep it to one file per run — the digest is built for depth on one document, not breadth across many. The original is never modified or moved; Cowork only reads it.

Step 2 — Paste this into Cowork

Open Claude Cowork in your working folder and paste the prompt below. It's ready to run as-is — if anything is unclear (more than one file in inbox/, or a scanned document with no selectable text), Claude will ask before going ahead rather than guess.

Read the document I want digested — the single file in the inbox/ folder (or if there's no inbox/ folder, the one document in this folder). It's a long legal document — a contract, deposition transcript, brief, or regulatory filing.

Do this:
- Read the whole document. Tell me the page count first, and confirm the text is selectable (not a scan).
- If it's long (more than ~20 pages), read it section by section using sub-agents in parallel, then combine the section summaries so nothing in the middle is missed. If it's short, just read it straight through.
- Write outputs/DIGEST.md with these sections: Document & parties; Key terms & obligations; Deadlines & dates; Risks & unusual clauses; Open questions. End every point with the page it came from, like (p. 14).
- Write outputs/TIMELINE.md — every dated event, in order, each citing its page.

Rules:
- Don't make anything up. If the document doesn't say it, don't write it.
- If a passage is ambiguous or you're unsure, put it under "Open questions" with the page number instead of guessing.
- Leave the original file in inbox/ untouched.
- End the digest with: "Attorney review required before any external use. Verify every citation against the source document."

If anything is unclear — more than one file in inbox/, or a scanned document with no selectable text — ask me before going ahead.

What Cowork does

For a long document, Claude doesn't read front-to-back in one pass. It splits the document into sections and hands each one to its own sub-agent; they read in parallel, then a final pass stitches their summaries together. That's why the middle of a 90-page agreement doesn't get lost. Here's what you'll watch:

Reading inbox/Settlement-Agreement.pdf … 84 pages, text selectable

  ├─ §5  Termination ................... done

What you get

A digest you skim, then verify against the pages it cites — and a timeline you can drop into a chronology.

What outputs/DIGEST.md looks like

Plain markdown, every claim tied to a page:

# Digest — Settlement Agreement

## Document & parties
- Settlement and release agreement between Acme Servicing LLC and J. Borrower. (p. 1)
- Effective date: 2025-03-01. (p. 1)

## Key terms & obligations
- Acme to credit the account $4,200 and correct the tradeline within 30 days. (p. 3)
- Borrower to dismiss the pending complaint with prejudice. (p. 4)

## Deadlines & dates
- Tradeline correction due 2025-03-31 (30 days from effective date). (p. 3)
- Release effective only upon payment clearing. (pp. 4–5)

## Risks & unusual clauses
- Non-disparagement clause is mutual but unusually broad. (p. 6)
- No-admission-of-liability language carved out for regulatory inquiries. (p. 6)

## Open questions
- "Account" is defined two ways (recitals vs. §2) — confirm which controls. (pp. 1, 3)  [low confidence — flagged]
- Governing-law clause names a state but no venue. (p. 7)

---
Attorney review required before any external use. Verify every citation against the source document.

Reusable recipe lives at recipes/document-digest.md.

Make it reusable

If you run this often, you don't have to paste the prompt every time. A power user can save it as a reusable skill in Cowork (or a /document-digest command in Claude Code) so it's one click. The text in recipes/document-digest.md is that saved version, ready to drop in.

Why it matters

The hard part of a long document isn't reading it once — it's not losing the clause on page 52 that changes everything. The section-by-section fan-out reads the whole thing without dropping the middle, and the page cites turn "trust me" into "check page 52." You stay the reviewer; Claude just gets you to the right pages faster.
